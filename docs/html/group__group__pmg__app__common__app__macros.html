◆ CY_APP_BC_DCP_DETECT_TIMER_PERIOD

#define CY_APP_BC_DCP_DETECT_TIMER_PERIOD   (1100u)

T_GLITH_DONE time waiting for the portable device to complete detection.

This is used by QC/AFC devices to proceed with subsequent detection.

◆ CY_APP_BC_APPLE_DETECT_TIMER_PERIOD

#define CY_APP_BC_APPLE_DETECT_TIMER_PERIOD   (5u)

Debounce time to verify if the attached device is Apple or not.

Apple devices create a glitch on DP line whereas BC devices continue to drive DP lower. This period is used when Apple and BC 1.2 source protocols are supported together.

◆ CY_APP_BC_GLITCH_BC_DONE_TIMER_PERIOD

#define CY_APP_BC_GLITCH_BC_DONE_TIMER_PERIOD   (1500)

TGLITCH_BC_DONE timer period.

This timer is used in sink mode to detect QC charger.

◆ CY_APP_BC_GLITCH_DM_HIGH_TIMER_PERIOD

#define CY_APP_BC_GLITCH_DM_HIGH_TIMER_PERIOD   (40)

T_GLITCH_DM_HIGH timer period.

After DCP opens D+/- short, the sink must wait for this time before requesting VBUS.

◆ CY_APP_BC_V_NEW_REQUEST_TIMER_PERIOD

◆ CY_APP_BB_ON_TIMER_PERIOD

#define CY_APP_BB_ON_TIMER_PERIOD   (250u)

Billboard ON delay timer period (in ms).

This should be long enough for a host to properly recognize the disconnection and reconnection of the USB Billboard device.

◆ CY_APP_INITIATE_PR_SWAP_TIMER_PERIOD

#define CY_APP_INITIATE_PR_SWAP_TIMER_PERIOD   (450u)

Time delay between successive PR_SWAP attempts (in ms).

PR_SWAP attempts are kept slow to allow other sequences such as alternate mode negotiation to complete.
